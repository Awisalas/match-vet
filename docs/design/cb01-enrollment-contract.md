# CB01 chronological enrollment contract

Contract draft `cb01-v1`, reviewed 2026-10-05 for [#72](https://github.com/Awisalas/match-vet/issues/72). The technical decisions below replace the issue's local-clock chronology rule. Implementation remains blocked on the service-use finding below. This document authorizes no implementation.

## Chronology and dependency order

One exact F06 INCLUDED fixture and exact frozen Preference Profile define a fixture batch. Derive its complete enabled-preference denominator from that Profile, never from available predictions or the Primary Recommendation.

1. Build one canonical `PreEnrollment` for each expected enabled preference, including incomplete and excluded entries. It retains the exact prediction and support state, with no outcome, F19 reference, timestamp token, batch root, or final EnrollmentRecord digest.
2. Build one canonical `FixtureEnrollmentBatch` containing contract version, exact F06/F07/F10/F11/F13/F14/F16 lineage, fixture and controlling revision, kickoff and cutoff, exact Profile identity, full expected denominator, and every PreEnrollment digest. Sort entries by exact preference ID. The batch contains no request, response, witness, final record, or publication receipt digest.
3. SHA-256 the batch's exact canonical bytes. Persist a DER RFC3161 request with that SHA-256 imprint, fresh positive cryptographically random nonce and `certReq=true`. Retain the selected trust-policy identity in immutable attempt metadata alongside the request. Submit one request for the fixture batch, rather than one per preference.
4. Retain the raw response. Verify exact granted status `0`, SHA-256 algorithm and 32-byte imprint, exact request nonce, CMS signature, signing-certificate identity, critical exclusive timeStamping EKU, accepted token policy, pinned chain, validity and required revocation evidence. Status `grantedWithMods` is rejected by v1.
5. Require signed time strictly `F07 cutoff < TSA genTime < controlling kickoff`. Compare exact UTC instants at retained precision, without rounding to seconds. Local ArtifactStore times are metadata. HTTP Date, Git time and phone time establish no chronology.
6. Only after verification publish final `EnrollmentRecord` artifacts referencing their PreEnrollment, batch digest/root, exact raw request and response digests, verification identity, and exact trust-policy/material version and digest. Publish one `FixtureEnrollmentPublication` receipt last, listing all expected preferences and final record digests. A reader accepts a live batch only through this complete verified receipt.

The digest dependency graph is PreEnrollment -> batch -> request/response verification -> final records -> receipt. No witness appears in the bytes it witnesses. A batch witness establishes that its committed bytes existed by the TSA's asserted time. It does not prove they were first created after cutoff, prove truthful source facts, or prove that input observations were genuinely available at cutoff. Existing F07/F11/F13 cutoff and leakage rules still apply. Missing accuracy remains unspecified; this contract claims signed `genTime` ordering, without inventing a physical UTC accuracy bound.

Unavailable, rejected, malformed, wrong-imprint, wrong-nonce, wrong-signer, unverifiable-chain or revocation evidence, out-of-window time, missing denominator, or changed Profile, fixture or F16 lineage cannot produce `ENROLLED_LIVE`. Preserve explicit failure reasons and every expected row. A successfully witnessed batch may contain incomplete/excluded rows, which remain incomplete/excluded individually.

## Canonical artifacts and identities

Use protected ArtifactStore objects and the existing canonical JSON convention: UTF-8, ASCII escapes, sorted object keys, compact separators, finite JSON numbers, and no NaN or Infinity. Reject duplicate keys, unknown fields, unsupported schemas and noncanonical bytes on replay. Every schema has an exact key set. An absent value is an explicit null paired with an availability state and reason, rather than an omitted key. Normalize offset-aware identity timestamps to UTC without losing fractional precision. DATE precision cannot establish a kickoff boundary. Preserve existing F13 artifact bytes and numerical representations exactly; do not reserialize or round distributions to construct a convenient forecast.

New CB01 ArtifactStore digests use lowercase bare 64-hex SHA-256, matching its protected artifact APIs. Preserve exact upstream identifier spelling, including F06/F07 prefixed identities, and validate the namespace before comparing underlying digest bytes. Never rewrite an identity passed to its upstream replay API. Use explicit schema/media-type and contract versions, sorted unique set-valued identities/reasons, and ordered arrays where order has model meaning. A CB01 artifact's own digest is calculated outside its payload. Original request and response are raw DER artifacts; certificate fingerprints hash certificate DER, rather than PEM text.

The immutable denominator anchor is exact F06 freeze digest, included membership and controlling revision, exact F07 cutoff identity/policy, and exact Profile digest/version. It exists independently of F16 availability. Missing F16 manifest/match result or other prerequisite is represented with null plus explicit reason. This supports incomplete rows without inventing lineage. Live rows require every mandatory lineage identity to replay and agree. Do not manufacture partial F16 manifests.

`PreEnrollment` retains that anchor; exact F10 requirements/catalog; F11 evidence; F13 input/result, retained history, model/algorithm/configuration, fit, raw and calibrated artifacts; F14 Profile/decision/RESEARCH_ONLY policy; F16 whole-freeze manifest/match result; software and schema identities; fixture teams/roles/competition/Matchweek; preference family, side, exact line, phase and topology; and disposition/reasons. Bind every family raw distribution, uncertainty, calibration and availability, not merely the selected preference probability. Exact embedded fields must agree with the retained F13 bytes. Missing values remain unavailable, never zero.

Retain explicit PRESENT, ABSENT, UNKNOWN or UNPERFORMED support states and reasons for CandidateInput, research, adversarial review, calibration, baseline, uncertainty validation, independent references, G6, G7 and paired Selection Strength. No unknown support becomes favorable by default. Later support requires a separately identified later assessment and cannot rewrite the witnessed state.

The batch binds the common denominator anchor and every row's exact available lineage, so shared and preference-specific references are both covered. Its expected IDs must equal the Profile's IDs exactly, with one row per ID and no duplicates or extras. Whole-freeze inspection derives all F06 INCLUDED fixture × enabled preference pairs and joins exact receipts or failure records. An unattempted fixture remains `INCOMPLETE_FOR_NOT_ATTEMPTED`; absent records cannot shrink the denominator. F06 excluded memberships remain visible under F06's own reasons and are not live target cases.

Case identity is contract version plus the complete exact denominator anchor and F06/F07/F10/F11/F13/F14/F16 lineage, including explicit missing states. Identical prepared inputs produce identical PreEnrollment and batch digests. Changed inputs produce a distinct case/batch and invalidate reuse of the prior token for those inputs. Keep all prior batches and failures visible. Alternative forecasts share the fixture grouping and cannot count as independent observations.

Anchor references must be PRESENT before preparing a batch. Unresolved anchors fail preparation; the exact F06/Profile denominator still exposes their missing cases.

READY_FOR_WITNESS requires all mandatory References PRESENT and consistent. `Preference` has `id`, `catalog`, `family`, `side`, `line`, `phase`, `settlement_topology`; retain the catalog's exact value types and nullability. `Forecast` has `result_reference` and `families`. Its `families` array contains one entry per exact F13 family, in family-ID order, with `family_id`, `input_reference`, `fit_reference`, `prediction_reference`, `calibration_reference`, and `retained_family_payload`. `Support` has `candidate_input`, `research`, `adversarial_review`, `calibration`, `baseline`, `uncertainty_validation`, `independent_reference`, `g6`, `g7`, `paired_strength`, all References. `Eligibility` has `calibration`, `data_quality`, `reliability`, `baseline`, `adversarial_risk`, `g6`, `g7_reference`, `paired_strength`, `policy_validation`; each contains exact `state=NOT_ASSESSED`, `reasons`, `supporting_digests`. Subsequent methodology assessments are separate artifacts rather than changing these keys.

`BatchEntry` has `preference_id`, `pre_enrollment_digest`, `disposition`, `reasons`. `PublicationEntry` has `preference_id`, `enrollment_digest`. Ordered certificate chains run signer to anchor. `TsaIdentity` has `status`, `imprint_algorithm`, `imprint_hex`, `nonce_hex`, `policy_oid`, `serial_hex`, `gen_time_utc`, `accuracy`, `signer_fingerprint`, `issuer`, `certificate_serial_hex`, `ess_binding`. Keep source assertion identity sets sorted; preserve complete original evidence snapshots rather than losing provenance through this projection.

`TrustPolicy` has exact body keys `policy_id`, `policy_version`, `material_digest`, `endpoint`, `imprint_algorithm`, `cms_digest_algorithm`, `cms_signature_oid`, `allowed_token_policy_oids`, `signer_fingerprints`, `intermediate_fingerprints`, `anchor_fingerprints`, `partial_chain`, `certificate_time_basis`, `revocation_policy`, `transport_limits`, `request_budget`, `terms_evidence_digests`. Their request budget/cadence and terms fields remain unresolved under the blocker below; they must be frozen before any v1 enrollment. No default value may silently clear that blocker.

## Repository ownership and recovery

Proposed public seam, not existing code:

```text
BootstrapRepository.enroll_fixture(exact_denominator_anchor, exact_lineage,
                                  trust_policy_digest) -> BatchResult
BootstrapRepository.resume(batch_digest, exact_attempt_digest,
                           retry_failed=False) -> BatchResult
BootstrapRepository.replay(publication_digest, exact_attachment_digests) -> CaseView
BootstrapRepository.inspect_denominator(freeze_digest, profile_digest,
                                       exact_publication_digests) -> DenominatorView
BootstrapRepository.attach_outcome(enrollment_digest, settlement_digest,
                                  exact_fact_evidence, predecessor_digest) -> OutcomeAttachment
```

One repository owns serialization, exact lineage validation, denominator, witness transport/verification, idempotency and publication. The caller supplies identities and receives exact artifact references. Internal stages are prepare, retain request, retain response, verify, publish records, publish receipt. Do not expose shell commands or transport objects as the enrollment API.

Serialize mutation under the existing writable Store lifetime and writer lock. ArtifactStore publishes individual catalog entries; it does not supply a multi-artifact transaction. The final receipt provides complete-batch visibility. A crash after some records but before the receipt leaves staged records, not a partially live batch. Resume validates and reuses exact artifacts, creates the remaining identical records, and publishes the receipt last.

Retain the nonce/query before sending. Normal exact-input replay of a successful batch makes no network call. A failed or lost response remains an exact failed attempt with reasons. `resume(..., retry_failed=True)` is the explicit operator request for another bounded attempt over the unchanged batch before the witness deadline; retain every attempt and reuse neither nonce nor response across distinct attempts. Select the exact successful attempt explicitly. A lost response that was never retained supplies no witness evidence.

A retained valid in-window token can support finalization after reopening, including after kickoff, because final publication time is local metadata. Reverify the exact prepared bytes, request, response, trust material and all source references. A digest-valid file orphan alone cannot establish live status; only exact artifacts reconciled into the protected catalog, with the complete verified receipt, may become visible. A new token with `genTime >= kickoff` cannot repair a missing witness. A post-kickoff rebuild or changed lineage cannot reuse an earlier token. Conflicting records/receipts for the same exact successful batch identity fail closed. Replay selects exact receipt and attachment digests, with no implicit latest pointers.

The Termux operator workflow uses `open_store` with the existing private store and writable lock, instantiates the proposed repository, inspects exact retained F06/Profile/F07 and F16/F13/F14/F11 identities, and invokes `enroll_fixture` per INCLUDED fixture. Save returned batch/attempt/receipt digests and incomplete reasons. Reopen and call `resume` with exact IDs after interruption. Later create/correct F19 through its existing API and attach the exact settlement digest. The implementation must document a runnable Python example using real constructor signatures. No F18 CLI command or rerun of valid acquisition, F11, F13 or F14 work is needed.

## TSA trust and revocation policy

Proposed policy `cb01-digicert-rfc3161-v1` pins independently downloaded official HTTPS material and token policy OID `2.16.840.1.114412.7.1`. Retain certificate DER, download provenance, DER fingerprints and exact material manifest digest. The observed chain has these SHA-256 certificate fingerprints:

| Material | DER SHA-256 fingerprint |
| --- | --- |
| DigiCert Trusted Root G4, cross-signed by DigiCert Assured ID Root CA | `33846b545a49c9be4903c60e01713c1bd4e4ef31ea65cd95d69e62794f30b941` |
| DigiCert Trusted G4 TimeStamping RSA4096 SHA256 2025 CA1 | `ca0b1554ecd901ea19dcad8749e9f2648c8d6dfcea1add9d2c2109415bb82ccd` |
| DigiCert SHA256 RSA4096 Timestamp Responder 2026 1 | `2da09da7f4131f9fe72db6c5e6e9c9656755af043f1ea742cc0d2120e141ebfc` |

Explicitly accept the pinned cross-signed G4 certificate as the partial-chain trust anchor used by the spike. Disable system CA-path/store trust and accept no response-supplied anchor. Require the exact pinned signer and intermediate; unexpected rotation fails until an independently reviewed new material/policy version exists. Old records keep their original versions. Signer identity includes certificate DER fingerprint, issuer/serial and ESS signing-certificate binding, not subject text alone. Retain token serial/policy/genTime/accuracy, selected chain fingerprints, verifier software/version/options and machine-readable verification results, alongside raw query/response and certificate material.

Validate the complete selected chain's certificate validity at token `genTime`, using OpenSSL `-attime` and timestamp-signing purpose. Preliminary unsigned time parsing supplies a candidate verification instant; trust it only after successful token signature verification. Never disable lifetime checking or use current phone time. Pin algorithms to SHA-256 imprint and the inspected RSA4096 certificate profile with SHA-256 certificate signatures, SHA-256 CMS digest and CMS rsaEncryption signature algorithm OID `1.2.840.113549.1.1.1`; reject unsupported algorithms rather than silently broadening acceptance.

Revocation decision: v1 requires retained signed CRLs for the signer and each non-anchor CA in the accepted chain. OCSP is not implemented as a second path in v1. Check issuer/signature, CRL scope and complete applicable coverage, `thisUpdate <= genTime < nextUpdate`, and certificate serial status. Missing nextUpdate, missing/stale/wrong-issuer CRL, unsupported delta/indirect scope, or a listed revoked serial fails closed. Conservatively reject a listed serial even if its revocation date is later. Pin the explicit trust anchor under the material policy rather than claiming its non-revocation from a missing issuer chain. Preserve exact CRL bytes/digests, issuer fingerprints, update times and decisions for offline replay. Historical replay uses these exact retained CRLs, never an implicit fresh network status.

This supplies the declared evidence check at enrollment; it does not certify perpetual non-compromise or long-term archival trust. Later compromise information requires a separately versioned explicit trust assessment, without rewriting prior artifacts or silently changing historical replay. `NOT_CHECKED` describes the spike and incomplete attempts only, and cannot establish v1 live enrollment. DigiCert's CP/CPS v7.09 section 1.3.4 requires status checking before reliance. [CP/CPS](https://www.digicert.com/content/dam/digicert/pdfs/legal/digicert-public-trust-cp-cps-v7-09.pdf#page=11)

Send only the digest-bearing query to the documented HTTP RFC3161 endpoint. Transport may deny availability, but cannot substitute an accepted token without signature/imprint/nonce checks. Apply finite connect/read/response-size limits. No automatic fallback TSA, local timestamp, HTTP Date or Git evidence is allowed.

## Outcome facts and correction contract

F19 retains complete supplied T10 `SettlementEvidence` snapshots, including the six optional regulation counts and source/revision/assertion/time/provenance fields. These schemas cover all four current F13 families. They do not guarantee those counts are actually supplied. A preference grade evaluates its required facts and cannot establish completeness or conflict resolution for another family's diagnostic.

`OutcomeAttachment` names exact EnrollmentRecord, F19 settlement version and evidence digest, F16 manifest/match result, F14 decision, fixture and preference. Require equality with witnessed lineage. Retain WIN, LOSS, PUSH and VOID separately; PENDING and CONFLICTING remain unresolved. Attachments are append-only full replacement snapshots with predecessor digest and sequence. One predecessor permits one distinct successor, and identical retries replay. Selecting a later unresolved version makes that view unresolved again. No sticky SETTLED state or silent latest settlement is permitted.

Include a minimal `OutcomeFactAttachment` in the outcome attachment when distribution evaluation is requested. It records exact F19 snapshot and any supplemental exact T10 evidence snapshot digests, selected source record/evidence/assertion/revision identities, fixture/teams/competition/controlling kickoff binding, source authority and fact-resolution rule version, publication/observation/retrieval times as supplied, six nullable counts with availability/reasons, and per-family resolution states. Supplemental evidence is retained as exact source facts, never inferred from a settlement label. It does not silently correct the F19 grade; use an explicit F19 successor if grading changes.

| F13 family | Required observed facts |
| --- | --- |
| Full-time goals | Regulation full-time home and away goals |
| First-half goals | Full-time and first-half home and away pairs, using T10's coherent half-goal fact set and valid played/phase context |
| Second-half goals | Both full-time and half-time pairs; derive each team's FT minus HT under existing T12 consistency rules |
| Corners | Regulation full-match home and away corners |

Resolve each fact set under T10's source hierarchy, supersession and conflict semantics. Keep fact sets coherent; do not combine incompatible source revisions or select lower-authority facts to remove a conflict. Validate nonnegative integer counts, phase/extra-time boundaries, completed regulation where required, no administrative result masquerading as played counts, exact fixture binding and HT <= FT. Missing times stay UNKNOWN and cannot establish later-methodology availability by a derivation cutoff. Unknown, pending, conflicting, void or incomplete facts cannot become zeros, counts reverse-engineered from a grade, or evaluable family outcomes. Keep each affected family unavailable. Other complete compatible families remain separately identifiable for later #70 assessment.

## Eligibility, boundaries and future checks

All methodology-specific eligibility dimensions start `NOT_ASSESSED`, with reasons and supporting identities: calibration, Data Quality, reliability, baseline, adversarial risk, G6, G7/reference, paired Selection Strength and policy validation. Only a separately frozen exact #70 assessment can set eligibility. Enrollment, timestamp verification, settlement and count completeness never do so. CB01 assigns no cohort/fold roles, estimators, thresholds, precision criteria or statistical sufficiency.

The future implementation's behavior checks belong at the public repository seam with a reopened real ArtifactStore and retained deterministic RFC3161 fixtures. Cover canonical bytes, full fixture × preference denominator, all cutoff/kickoff equality boundaries, malformed/rejected/wrong nonce/imprint/signer/chain/CRL, timestamp failure retention, no outcome leakage, changed lineage, exact replay/idempotency, interrupted publication and recovery, no upstream reruns, every F19 state, corrections back to unresolved, count-fact absence/conflict and refusal to promote eligibility. Offline fixtures alone must not claim that a network service permits this use. This review runs document/repository checks only.

F17 remains blocked by F16 and #70. F18 and F20 keep their blockers. Once this contract is ready, add CB01 before F17 outside the original numbered tickets. It depends on the existing F06/F07/F10/F11/F13/F14/F16/F19 and ArtifactStore contracts, not #70 completion. F21 must adopt the same CB01 PreEnrollment/batch/record/attachment identities when integrated collection arrives, preserving prior witnesses and grouping rather than replacing or re-enrolling cases.

## Review synthesis and blocker

Candidate A proposed batch-atomic visibility through a publication receipt. Candidate B proposed explicit prepare/witness/finalize APIs. Select A's smaller public enrollment interface and graft B's retained internal stages and explicit exact-attempt resume. Both identified missing-F16 denominator handling, in-window witness recovery after kickoff, and the difference between F19 grade sufficiency and count-fact sufficiency. The receipt avoids new Store transaction machinery. Exposing all stages would make the operator coordinate invariants owned by the repository.

The safety argument is source-grounded: no production source is changed, and F17's #70 gate is preserved. ArtifactStore's per-object publication and F19's retained evidence shapes were inspected. Future crash/revocation/chronology behavior is not runtime-proven because CB01 is not implemented. The prior Termux spike proves only its recorded protocol/signature checks, not these future behaviors.

Remaining material blocker: no applicable primary-source DigiCert terms or provider confirmation has been found establishing permission for arbitrary non-code-signing fixture commitments and suitable rate limits for this bounded workload. The public endpoint and successful request prove access, not service entitlement. CP/CPS section 6.8 recommends signed-code timestamping but supplies no quota or explicit permission for this use. Website terms explicitly exclude product/service use. [Endpoint documentation](https://knowledge.digicert.com/general-information/rfc3161-compliant-time-stamp-authority-server), [CP/CPS section 6.8](https://www.digicert.com/content/dam/digicert/pdfs/legal/digicert-public-trust-cp-cps-v7-09.pdf#page=77), [website terms](https://www.digicert.com/security-terms)

Closure requires retained applicable terms or DigiCert confirmation covering non-code-signing Research-Only commitments, cost/account requirements, and permitted cadence/volume. Proposed load is one successful token per exact fixture batch, no per-preference requests, no concurrency and no automatic retries. Freeze the permitted request budget/cadence from that evidence before implementation. Do not substitute an invented numerical limit or another service's terms. Keep #72 OPEN / needs-triage and do not code. Roadmap insertion remains conditional on closing this blocker.
